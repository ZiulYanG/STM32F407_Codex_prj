# Application scripts

Open a normal Windows CMD in the `Application` directory, then run:

```cmd
python script\build.py
python script\flash.py
python script\verify_spi_nor.py
python script\test_storage.py
python script\test_ymodem_storage.py
python script\test_ymodem_hardware.py --port COM3
python script\storage_soak.py --cycles 20
```

`build.py` runs the Debug CMake preset and generates `build\Debug\Application.elf`, `.bin`, and `.hex`.

The SPI NOR destructive startup self-test and the reversible 24C02 startup
self-test are enabled only by the Debug build. Release, RelWithDebInfo, and
MinSizeRel compile both out. Every build validates the `app_main.c` defines,
ELF markers, and self-test symbols before generating BIN/HEX artifacts.
It also rejects CubeMX/source drift that changes the default task, Serial
Manager task, two TX queues, or RX StreamBuffer back to dynamic allocation.
The policy additionally checks that only Serial Manager calls the USART1 BSP
write function.

The canonical APP linker script is `linker\STM32F407ZGTx_APP_FLASH.ld`. It is
kept outside the files regenerated by CubeMX and fixes the APP partition at
`0x08040000` with a length of 768 KB.

`flash.py` uses the DAPLink CMSIS-DAP interface to program the APP image at `0x08040000`, verify it, and reset the MCU. After reset, the Bootloader validates the vector table and jumps to the Application.

Both scripts reject an ELF/HEX image that does not start at `0x08040000` or
extends beyond `0x080FFFFF`. This prevents a CubeMX-regenerated full-device
linker script from producing an image that could overwrite the Bootloader.

`verify_spi_nor.py` requires `pyserial`. Despite its legacy filename, it now
verifies both external storage devices. It opens COM3 before resetting the
target through DAPLink and captures the Bootloader/Application startup log.
The SPI NOR checks still use only the final 4 KB sector at `0x00FFF000`. The
test reaches that sector through the bounded `driver_test` partition view.
24C02 Debug test backs up `0xF6-0xFF`, performs a cross-page write and negative
boundary checks, then restores and verifies the original bytes. Release must
report both self-tests as `DISABLED`, while the JEDEC and EEPROM address probes
remain enabled. All modes require `APP log drops : 0`, Console mode, a healthy
Serial Manager stack, and zero startup RX drops/hardware errors.

`test_storage.py` builds and runs the HAL-independent storage Interface tests
with the installed host GCC. It checks lifecycle, range validation, erase
alignment, capability rejection, and Adapter call behavior without hardware.
It also verifies partition address translation, isolation, definition
validation, and shared-parent lifecycle behavior.

`test_ymodem_storage.py` verifies the sequential File Sink/Source Adapter and
4 KB erase-on-demand policy. `test_ymodem_hardware.py` performs a real COM3
round trip: it receives 2500 bytes into the Candidate partition, requests the
same bytes back from the MCU, and compares the complete payload. It modifies
the beginning of Candidate and must not be used while a valid pending upgrade
is stored there.

`storage_soak.py` repeatedly programs/resets the Debug image and reuses the
canonical hardware verifier. Each boot first checks that the Driver Test
partition retained the erased state left by the previous boot, then performs
the complete destructive test and cleanup. It also requires both storage
devices, all partitions, RTOS resource health, and zero log drops on every
cycle. Use only the reserved Driver Test partition.

Useful options:

```cmd
python script\build.py --clean
python script\build.py --preset Release
python script\flash.py --adapter-speed 100
python script\flash.py --dap-serial B1897547C3840B15B1FE4CDBBF997647
python script\build.py --preset Release --clean
python script\verify_spi_nor.py --image build\Release\Application.elf --expect-self-test disabled
```
